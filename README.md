# english-speaking-prototype

Офлайн-озвучка английских текстов для уроков. Этап 1 — **бенчмарк**: выясняем,
какой движок (Kokoro или Piper) тянут школьные ноутбуки, и выбираем голоса на слух.

## Что внутри

| Файл | Зачем |
|---|---|
| `prepare.bat` / `prepare.ps1` | **дома, с интернетом**: качает Python 3.12 (embeddable), пакеты и модели в `runtime\` и `models\` (~900 МБ) |
| `run_bench.bat` | замер скорости всех движков на этом компьютере |
| `make_samples.bat` | образцы всех голосов для прослушивания |
| `bench/bench.py` | сам бенчмарк (каждый движок — в отдельном процессе) |
| `tools/pack_kokoro_voices.py` | собирает голоса Kokoro в `voices.npz` |

Движки в замере:

- **kokoro-fp32** — Kokoro-82M, полная модель (325 МБ), лучшее качество;
- **kokoro-int8** — та же модель, сжатая (92 МБ), меньше памяти;
- **piper-medium** — Piper, голос `en_US-lessac-medium`, быстрый;
- **piper-high** — Piper, `en_US-lessac-high`, качественнее, медленнее.

## Порядок действий

1. **Дома** запустить `prepare.bat`. Если HF не отвечает, скрипт сам попробует
   зеркало hf-mirror.com; при обрыве можно просто запустить его ещё раз — скачанное
   повторно не качается. В конце будет самопроверка (`kokoro: OK`, `piper: OK`).
2. Скопировать папку на флешку (`.git` и `.cache` не нужны).
3. **На каждом ноутбуке**: лучше скопировать папку на диск (с флешки модели грузятся
   медленно и время загрузки будет завышено, но сам синтез это не искажает),
   запустить `run_bench.bat`. На Atom весь прогон может занять 10–15 минут.
4. На i5 (или дома) запустить `make_samples.bat` и вместе с учительницей послушать
   `results\<ИМЯ_ПК>\samples\*.wav`.
5. Привезти обратно папку `results\` — там для каждого компьютера `results.txt`,
   `results.json` и wav-файлы.

Отдельные движки: `run_bench.bat --engines kokoro-int8,piper-medium`.

## Как читать результаты

- **×РВ** — во сколько раз синтез быстрее реального времени. Меньше 1 — машина
  не успевает читать «вживую».
- **Старт** — сколько ждать первый звук после нажатия Play (синтез первого предложения).
- **Заикание** — самая длинная пауза между предложениями при чтении на лету
  (если короткое предложение идёт после длинного, следующее может не успеть).
- **Память** — пик RAM процесса. На ноутбуке с 4 ГБ всё, что больше ~1,5 ГБ, — риск.

Для сравнения — облачная VM, 2 ядра Xeon 2.8 ГГц (Linux):

| Движок | ×РВ | Старт | Память |
|---|---|---|---|
| kokoro-fp32 | 1.4 | 1.15 с | 580 МБ |
| kokoro-int8 | 1.5 | 1.15 с | 360 МБ |
| piper-medium | 14 | 0.13 с | 280 МБ |
| piper-high | 2.3 | 0.6 с | 320 МБ |

## Если что-то не так

- **«32-bit Windows»** — сборка только под 64-битную Windows.
- **Ошибка DLL / `onnxruntime` не загружается** — на ноутбуке нет Visual C++.
  `prepare.ps1` кладёт нужные `msvcp140*.dll` рядом с `python.exe`, но если на
  домашнем ПК их не нашлось, он скачал `vc_redist.x64.exe` — установить его на ноутбуке.
- **Процесс падает без ошибки на Atom** — пришли `results.json`, разберёмся
  (подозреваемые: нехватка памяти для fp32 или инструкции процессора).
